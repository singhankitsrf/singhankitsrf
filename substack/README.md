## Publishing cadence

**Long form:** one substantial article every two weeks.  
**Notes:** 2–3 useful engineering/research notes per week.  
**Monthly:** one synthesis post connecting lessons across multiple projects.  
**Quarterly:** one evidence review covering what was actually executed, measured and validated.

## Content standard

Each long-form post should include a concrete engineering problem, system-level explanation, architecture/flow where useful, explicit evidence boundary, inspectable project link, failure modes/trade-offs, practitioner conclusion and invitation to inspect code or a demo.

Avoid inflated claims, unsupported production metrics, generic AI-news commentary and repetitive tutorial content that does not reinforce the publication's identity.

## Growth system

1. Cross-link each Substack article from the relevant GitHub project and profile.
2. Add the final Substack URL to LinkedIn and Hugging Face where appropriate.
3. Publish a LinkedIn launch/share post for each major article.
4. Use Substack Notes for concise engineering observations, diagrams, paper takeaways and evidence updates.
5. Recommend only genuinely relevant AI/ML/research publications.
6. Optimize for useful technical discussion and recruiter/collaborator discovery, not vanity subscriber counts.

## Measurement dashboard

Track platform-reported subscriber growth, article views, open/click rates, subscriber sources, GitHub/Hugging Face referrals, saves/shares, practitioner replies and recruiter/collaboration conversations attributable to an article. Do not manufacture engagement metrics.

## Monetization position

Start free. The primary objective is authority, discoverability, collaboration and career leverage. Consider a paid tier only after consistent readership develops and there is a clear paid value proposition.
